# Visualization Rules

이 문서는 시장 맵, 섹터 맵, 종목 Overview 차트의 시각화 기준을 정의한다.
대시보드는 많은 데이터를 한 화면에서 빠르게 판단할 수 있어야 하므로, 색상/크기/위계가 일관되어야 한다.

## 선택 상태 모델

```text
selectedLevel = market | sector | stock
selectedSector = string | null
selectedStockCode = string | null
mapMetric = market_cap | trading_value
colorMetric = change_rate | volatility
period = 1D | 1W | 1M | 3M | 1Y
```

## 화면 밀도와 레이아웃 원칙

- 데스크톱 기본 화면은 `시장 맵 65~70% / 인사이트 패널 30~35%` 비율로 구성한다.
- 첫 화면에서 시장 맵, 핵심 요약, 인사이트 패널, 뉴스 요약이 한 번에 보여야 한다.
- 대시보드는 많은 데이터를 빠르게 판단하는 도구이므로 여백을 과하게 넓히지 않는다.
- 큰 hero, 랜딩 페이지형 문구, 장식용 배경, 마케팅식 카드 배치는 사용하지 않는다.
- 반복 카드와 패널의 border radius는 8px 이하로 유지한다.
- 그림자는 깊게 쓰지 않고, 구분은 배경 톤·경계선·간격으로 해결한다.
- 사용자 화면에는 `Harness Rules`, `OpenAPI Harness Demo`, `Mock`, `테스트 데이터` 같은 내부 구현 문구를 표시하지 않는다.

## 시장 맵 구조

- 초기 화면은 전체 시장을 섹터별 구역으로 보여준다.
- 섹터를 클릭하면 해당 섹터 안의 종목 맵으로 드릴다운한다.
- 종목을 클릭하면 종목 Overview 화면으로 전환한다.
- MVP 기본 형태는 섹터별 히트맵이다.
- 확장 형태로 산업 분야별 히트맵 또는 워드 클라우드형 종목 맵을 사용할 수 있다.
- 히트맵은 단순 카드 그리드가 아니라 treemap처럼 상대 크기와 밀도가 느껴져야 한다.
- 섹터 화면에서는 섹터 내부 종목 수 차이가 보이도록 종목 타일을 충분히 조밀하게 배치한다.
- 시장 맵 위에는 큰 KPI 카드 4개를 두지 않고, compact summary strip 또는 인사이트 패널 상단 요약으로 압축한다.

## 크기 규칙

- 박스 또는 버블 크기는 기본적으로 `market_cap`을 사용한다.
- `market_cap`이 없으면 `trading_value`를 사용한다.
- 거래대금 기준 보기에서는 `trading_value`를 크기 기준으로 사용한다.
- 너무 작은 종목은 최소 클릭 영역을 보장한다.
- 크기 계산은 raw 값을 그대로 쓰지 않고 `normalized_size_score`를 사용한다.
- 극단값은 clamp하여 한 종목이나 한 섹터가 화면을 과도하게 차지하지 않게 한다.
- 최소 타일은 이름과 등락률이 읽히는 크기를 보장하되, 전체 밀도를 해치지 않는다.

## 색상 규칙

- 색상은 기본적으로 `change_rate`를 기준으로 한다.
- 상승은 빨간 계열, 하락은 파란 계열을 사용한다. 국내 주식 사용자 관습을 우선한다.
- 보합 또는 변화 없음은 중립 회색으로 표시한다.
- `colorMetric = volatility`일 때는 변동성 크기를 색상 강도로 표시한다.
- 다크모드/라이트모드 모두에서 상승/하락 대비가 명확해야 한다.
- 색상 강도는 `normalized_change_rate`를 사용한다.
- 상승/하락 외의 색은 중립, 위험, 공시 강조 용도에만 제한적으로 사용한다.
- 화면 전체가 과하게 알록달록해지지 않도록 배경과 패널은 낮은 채도의 중립색을 사용한다.

## 진하기와 강조

- 색상 진하기는 등락률 크기 또는 거래량 증가율을 기준으로 한다.
- 거래량 증가율 100% 이상인 종목은 관심 증가 상태로 강조할 수 있다.
- 변동성이 최근 평균 대비 1.5배 이상이면 테두리로 위험 신호를 표시한다.
- 관련 공시가 있는 종목은 별도 아이콘 또는 테두리 표시를 사용할 수 있다.
- 위험 강조는 테두리, 작은 배지, 아이콘 중 하나만 사용한다.
- 강조 요소가 2개 이상 겹치면 공시 > 위험 > 관심 증가 순서로 우선한다.

## 우측 인사이트 패널

- `market` 상태에서는 전체 시장 인사이트를 표시한다.
- `sector` 상태에서는 선택 섹터의 인사이트를 표시한다.
- `stock` 상태에서는 종목 Overview로 진입하거나 종목 핵심 요약을 표시한다.
- 인사이트 문구에는 주요 지표 근거를 함께 보여준다.
- 인사이트 패널은 긴 설명 카드가 아니라 상태 라벨, 핵심 수치, 짧은 근거 row 중심으로 구성한다.
- 패널 상단 summary는 한 줄 결론과 핵심 지표 2개만 우선 노출한다.
- 개발자용 규칙 설명은 사용자 화면에 노출하지 않는다.

## 하단 뉴스/공시 바

- 하단 바는 항상 현재 선택 상태와 연결된다.
- 전체 시장 상태에서는 시장 전체 뉴스와 주요 공시를 보여준다.
- 섹터 상태에서는 해당 섹터 뉴스와 관련 종목 공시를 우선한다.
- 종목 상태에서는 해당 종목 뉴스와 공시를 우선한다.
- 하단 뉴스 바는 주요 히트맵을 덮는 fixed 카드로 만들지 않는다.
- 기본 형태는 대시보드 하단 band 또는 접히는 ticker로 둔다.
- 종목 Overview에서는 하단 fixed 뉴스 바보다 화면 내부 뉴스 섹션을 우선한다.
- 긴 뉴스 제목은 말줄임 처리하고, 상세는 클릭 또는 확장 영역에서 보여준다.

## 차트 규칙

- 종목 Overview의 기본 차트는 최근 1개월 일봉 라인 차트이다.
- 기간 선택은 `1D`, `1W`, `1M`, `3M`, `1Y`를 제공한다.
- 차트 하단에는 거래량 막대를 함께 표시한다.
- 확장 기능으로 캔들 차트, 이동평균선, 보조지표를 추가할 수 있다.

## 빈 데이터 fallback

- 섹터 데이터가 없으면 `미분류` 그룹에 배치한다.
- 가격 데이터가 없는 종목은 맵에서 제외한다.
- 뉴스가 없으면 하단 바에 빈 상태 문구를 표시한다.
- 차트 데이터가 부족하면 사용 가능한 기간만 표시하고 부족한 기간은 비활성화한다.

## 완성도 체크

- 첫 화면이 카드 모음처럼 보이면 실패로 본다.
- 히트맵의 상대 크기, 색상 방향, 위험 강조가 3초 안에 읽혀야 한다.
- 인사이트 패널은 시장 맵보다 시각적으로 더 무겁게 보이면 안 된다.
- 뉴스 영역은 보조 정보이며 히트맵이나 차트를 가리지 않아야 한다.
- 차트와 히트맵은 화면의 주인공이고, KPI와 뉴스는 보조 정보로 배치한다.
